## 1. 目标与非目标

**目标（对应 RFC M7）**：

1. `src/graph/`：图类型、条件 AST 解析器、DAG 校验、frontier 批量执行器、策略门、trajectory 记录。
2. `POST /v1/execute`：图执行端点 + conformance 契约用例。
3. 轨迹级校准报告：`zjev-traj` 工具输出 trajectory ECE/Brier，并与 node-level 指标**并排对照**——直接检验 quest1.md §12 的命题"单跳 calibrated ⇏ 轨迹 calibrated"。

**非目标**：

- 概率分支全展开（deferred crispification 的完备形态，见 §3 方案 C）——V0.2 用轨迹报告**度量**组合缺口，不实现概率遍历。
- WebSocket 流式、真实 ONNX 模型接入、zharness 集成（M6 属另一个仓库的编排问题）。
- 图循环（DAG only）、边的权重/优先级、子图复用。

## 2. 核心概念

### 2.1 图结构（JSON）

```json
{
  "graph": {
    "nodes": [
      { "id": "risk", "decision": "risk_level", "gate": { "threshold": 0.7, "action_above": "escalate", "action_below": "log", "action_abstain": "manual_review" } },
      { "id": "intervention", "decision": "needs_intervention" }
    ],
    "edges": [
      { "from": "risk", "to": "intervention", "when": "risk_level == high" }
    ]
  }
}
```

- `node.id`：图内唯一，解析期校验；空图（0 节点）→ 400 `invalid_graph`。
- `node.decision`：必须命中请求 `decisions[]` 中的某个 schema id；**且 1:1**——一个 schema id 最多被一个节点引用（engine 批内拒绝重复 schema id，N:1 在解析期直接拒绝并提示去重）。
- `node.gate`：可选。缺省 `"action_*"` 为字符串（透传给消费方，runtime 不解释语义）。
- `edge.when`：条件表达式字符串，**请求解析时一次性编译为 AST**，运行时只 evaluate AST，不做字符串 eval（RFC §7 硬约束）。

### 2.2 条件语法（EBNF）

```text
cond   := or
or     := and ("or" and)*
and    := not ("and" not)*
not    := "not" not | cmp
cmp    := operand (("==" | "!=" | ">" | "<" | ">=" | "<=") operand)?
operand := field | literal
field  := ident ("." ("value" | "confidence" | "abstention"))?   // 裸 ident ≡ ident.value
literal := number | '"' string '"' | bare_ident | "true" | "false"
```

- 语义来源：operand 为字段引用时，取值自**已执行节点**的 `DecisionResult`；裸 `ident == bare_ident` 匹配 prd.md §19 示例 `risk_level == high`（bare_ident 按 choice option 字符串匹配）。
- 类型规则（解析期针对请求内 schema 集合做静态检查）：
  - `.value`：choice→字符串比较（`>`/`<` 系非法，解析报错）；noul→`true/false`（`> < >= <=` 非法）；score→数值比较（`==/!=` 作用于 E[X] 数值）；rank→禁用（无标量值，解析报错）。
  - `.confidence`/`.abstention`：一律数值比较。
  - 布尔位置（如 `and` 的operand 缺省比较）：仅允许 noul `.value` 或裸字段。
- 运行时求值只可能失败一种情况：字段引用的决策尚未执行 → `error.ConditionDependency`（确定性顺序下属图构造错误，映射 400）。解析期能查的非法全部在解析期报。

### 2.3 执行语义（frontier 批量）

```
ready := 入度为 0 的节点（按 id 字典序排序）
循环直到 ready 为空：
    1. ready 中所有节点的 schema 一次性送 engine.run（共享一次 encoder 前向）
    2. 按 id 序逐节点：
       - 记录 trajectory step（result 全量概率形态）
       - 若有 gate：求值并记录 action
       - 按声明序逐出边：eval( when , 已执行结果集 ) → true 则激活目标节点
    3. ready := 新激活且未执行的节点（按 id 序）
```

- **激活规则**：节点的多条入边为 OR 语义——任一入边 fired 即激活；每节点最多执行一次。
- **短路**：条件为 false 的边被剪枝；若某节点的全部入边均未 fired，该节点及其独占下游被跳过，响应中 `skipped[]` 列出（可观测性，不重排语义）。
- **确定性**：frontier 内按 node id 字典序执行与激活；同一份请求+模型在任何机器上得到同一路径（mock 模式可复现，conformance 依赖此性质）。
- **终止性**：解析期 Kahn 算法判环，环即 400；DAG 保证循环 ≤ 节点数次。
- 条件求值环境 = 全部已执行节点的 DecisionResult（不止边源节点），支持 diamond-join 条件（如 `risk.confidence > 0.8 and risk.value == high`），文档明示。

### 2.4 策略门 gate.zig

```zig
pub const Gate = struct {
    threshold: f32,        // ∈ [0,1]，解析期校验
    action_above: []const u8,   // confidence ≥ threshold
    action_below: []const u8,   // confidence < threshold
    action_abstain: []const u8, // abstention ≠ null 且 ≥ threshold（优先判定）
    pub fn apply(g: Gate, r: DecisionResult) []const u8;
};
```

- 判定序：abstention 优先 → confidence。使用 engine 上报的 `uncertainty` 字段原值（choice 的 confidence 为选项概率最大值这一实现语义已在 RFC 附录示例中公开，维持兼容）。
- 纯函数、无 I/O；M6 zharness 以库形式直接调用，亦嵌入 executor 节点。

### 2.5 Trajectory 与轨迹概率（势）

每 step 记录 `{node_id, decision_id, result}`，执行顺序即路径。轨迹概率：

```
path_prob = ∏ m_i，m_i = 第 i 个已执行节点"脆化输出"的概率质量
```

| 类型 | m_i 定义 | 说明 |
|---|---|---|
| choice | `P(value)`（含 `__abstain__`） | 精确 |
| noul | `value==true ? P(yes) : 1−P(yes)` | 精确（注意 confidence 字段恒为 P(yes)，故单独定义） |
| score | `E[X]` 所在桶的桶概率 | 粗粒度，文档明示 |
| rank | top1 项的归一化分数 | 沿用 engine 归一化视口 |

`m_i` 计算实现固定在 `trajectory.zig`（`massFor(result, schema) f32`），executor 调用它；gate 不改动 m_i。abstention 发生时不中断路径：m_i 取 abstention 概率，路径继续（响应里 `value == "__abstain__"` 由消费方解释）。

### 2.6 轨迹校准口径（本版的核心交付）

命题（quest1.md §12）：单跳 calibrated ⇏ 轨迹 calibrated，`P(A,B,C) ≠ P(A)P(B)P(C)`。

**度量**而非假设：

- 数据集记录：`{ "state": {...}, "expected": { "<decision_id>": <value> } }`（value 规则同 crisp 相等：choice 比字符串、noul 比布尔、score 比 E[X] 所在桶序号、rank 比 top1 id）。
- 逐记录：执行图 → path_prob p、正确性 y（全部 expected 命中为 1，否则 0；expected 中未执行的节点按 miss 计，促使标注与图一致）。
- 聚合：`traj_brier = mean((p−y)²)`；`traj_ece` = 15 等宽 bin（沿用 calib/ece.zig 口径）|mean p − mean y| 加权。
- **并排对照**：同批数据同时输出 node-level ECE/Brier（对路径上每个决策单独算，已有 `calib/` 全套）与 trajectory-level。若 node-level ≈ 0 而 trajectory-level 显著偏高，即实证"校准不可简单串联"，这正是 quest1 §12 要验证的实验输出。

### 2.7 API

`POST /v1/execute`，请求体 = DecisionRequest + `graph` 字段。响应：

```json
{
  "trajectory": [ { "node_id": "risk", "decision_id": "risk_level", "result": { ...DecisionResult }, "action": "escalate" } ],
  "skipped": ["node_c"],
  "path_prob": 0.4621,
  "calibration": "matched"
}
```

- `action` 仅节点带 gate 时出现；`latency_us` 由传输层对每个 result 照常填充。
- 错误映射沿用 §9.4：图/条件解析失败 → 400 `invalid_graph`（带字段路径与原因）；`ConditionDependency` → 400 `invalid_graph`（依赖图构造错误，客户端可修）；模型/超时错误同 `/v1/decide`。
- 上限沿用全局约束：图节点数 ≤ 64（对齐单请求 decisions ≤ 64）。
- **实现登记偏差**：V0.2 图执行不经过 `scheduler` 队列（单飞批调度仅服务 `/v1/decide`；图执行的 frontier 批已在 executor 内完成，重复入队无收益）。若未来图执行需要跨请求聚合，再评估复用。

### 2.8 工具：zjev-traj

`zig build` 产出 `zjev-traj`：`--dataset traj.jsonl [--mock-mode m] [--profiles-dir d] [--model-name n] [--domain d]`（ stdout 打印报告 JSON）。

- **数据集行自包含**（实现期对原计划"共享 `--graph` 文件"的修正）：`{"state": ..., "decisions": [...], "graph": {...}, "expected": {"<decision_id>": <value>}}`，按行流式解析；`expected` 为空对象的行跳过并计入 `skipped_records`。
- score 的 int scale 期望值 = 桶序号整数（`round(E[X]) − min`）；labels scale 期望值 = 桶序号整数（区间校验从简，登记为已知简化）；choice/rank 期望值为字符串，noul 为布尔。
- 复用 `tools/bench.zig` 的模型/profile 装载风格；输出 `{"n", "trajectory_accuracy", "traj_brier", "traj_ece", "traj_mce", "skipped_records", "by_node":[{"id","n","accuracy","ece"}]}`——node-level 与 trajectory-level 并排，直接可读组合缺口。
- 样例数据集 `datasets/traj_sample.jsonl` 入仓（mock sequence 模式确定性可复现），报告记录于 `benchmarks/traj_2026-09-24.md`。

## 3. 方案取舍

### 方案 A（采纳）：frontier 批量 DAG 执行器 + path_prob 轨迹报告 + `/v1/execute`

- 优点：共享 encoder 前向（每 frontier 一次而非每节点一次，真实模型下延迟 ∝ frontier 数而非节点数）；语义确定性；轨迹报告直接产出 quest1 §12 的对照证据。
- 缺点：相比逐节点调用多一层 frontier 管理（约几十行，由 engine.run 既有批能力承接）。

### 方案 B：逐节点 engine 调用

- 优点：代码最少。缺点：state 每节点重编码一次；ModernBERT 规模下延迟随深度线性放大；与 engine 批能力重复。否决。

### 方案 C：概率分支全展开（无脆化遍历）

- 每条边携带概率质量双分支传播，路径枚举需上限与合并策略；完备实现 deferred crispification，但表面剧增（指数路径、跨 frontier 质量归并、响应 schema 大变）。V0.2 用方案 A 的**度量**先拿到组合缺口数据，若数据表明有必要，V0.3 再评估 C。登记为后续工作，不实现。

## 4. 模块与接口

```
src/graph/
├── types.zig      // Graph/Node/Edge/Condition（AST 类型也在此）
├── condition.zig  // 词法+递归下降解析 → AST；静态类型检查；eval( AST , []DecisionResult )
├── gate.zig       // Gate + apply
├── executor.zig   // frontier 执行、Kahn 判环、mass 计算入口
└── trajectory.zig // Step/Trajectory/path_prob 聚合
```

- 全部纯逻辑（无 std.Io、无网络），executor 仅依赖 `core/*`、`calib/*`、`model/factory`、`runtime/engine`，可在单测中以 mock 模型全速运行。
- `src/zjev.zig` 增 `pub const graph = @import("graph/...")` 各导出（**必须**加，否则 `refAllDecls` 静默跳过新模块测试）。
- API 层：`api/json.zig` 增 RawGraph 解析 + `writeExecuteResponse`；`api/routes.zig` 挂 `/v1/execute`。
- build.zig：新增 `zjev-traj` artifact（仿 bench）。

## 6. Zig 0.17 适配要点

- 无新增 extern/异步需求：executor 为纯同步逻辑，跑在 server fiber 内；不得引入 `std.Thread`（全局约束）。
- AST 节点用 arena 分配（请求级 arena，V0.1 既有约定）；容器一律 unmanaged + 显式 allocator。
- 递归下降解析深度由输入长度决定，条件字符串上限 1024 字节（解析期拒绝），无栈溢出面。
- `std.fmt.parseFloat` 解析数值字面量。词法消歧规则（文档明示）：比较左操作数一律按字段引用解析；右操作数中 `true/false` 为布尔字面量、引号为字符串字面量、数字为数值字面量、其余标识符为 bare_ident（option 名）。
- 新代码遵循 V0.1 已验证清单（refAllDecls、@splat、unused 参数 `_ = x` 等）。

## 8. 风险登记

1. score/rank 的 m_i 是粗粒度定义（桶概率/归一化 top1），轨迹概率对这两类节点的敏感性有限——已在 §2.5 明示，后续可用分桶标签细化。
2. `skipped[]` 语义在并行分支下仅列"未执行的节点"，不区分"被剪枝"与"不可达"，V0.2 保持简单，需要时再分级。
3. trajectory ECE 需要足够样本量才有统计意义，样例集仅演示管线，真实结论待 M3 真模型数据集复核。
